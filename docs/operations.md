# Эксплуатация

## Что уже настроено на этой машине

- MySQL 8, база `tg_message_collector`, UTF-8 (`utf8mb4`), даты UTC.
- `.env` с API credentials, номером, отдельными паролями базы и случайным `MCP_TOKEN`; права файла `0600`.
- Сборщик: `tg_collector@127.0.0.1` с `SELECT, INSERT, UPDATE`. DDL и удаление строк запрещены.
- MCP: `tg_reader@127.0.0.1` с единственным правом `SELECT` на базу проекта.
- MCP слушает исключительно `127.0.0.1:8765`. Нужен `Authorization: Bearer <MCP_TOKEN>`.
- Локальная quantized ONNX-модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384 измерения.
- Пользовательские systemd units включены. MCP запущен, сборщику необходима первая авторизация.

`.env`, `data/`, сессии и их журналы, модели, векторный индекс и логи исключены из Git.
Нельзя публиковать содержимое `.env` или Telegram-сессии.

## Telegram и история

```bash
.venv/bin/python app.py login-qr
systemctl --user start tg-message-collector
journalctl --user -u tg-message-collector -n 30 --no-pager
```

`login-qr` выводит QR прямо в интерактивном терминале и обновляет его при истечении срока.
В Telegram на телефоне открой **Настройки → Устройства → Подключить устройство** и отсканируй QR.
Если включена 2FA, введи пароль в терминале (ввод скрыт). Сохранять или пересылать QR не нужно.
Если старый `app.py login` ещё ожидает код, сначала заверши его через Ctrl+C.
Обычный вход по коду остаётся доступен: `.venv/bin/python app.py login`.

Оба варианта создают отдельную `data/collector.session`. Существующие сессии других проектов не копируются.
Повторный процесс сборщика/авторизации/индексации блокируется файловым lock.
Сервис никогда не начинает интерактивную авторизацию; при неготовой сессии ExecCondition пропускает запуск.
После успешной авторизации сервис нужно запустить командой выше.

Пустой `CHAT_IDS` означает все диалоги аккаунта, включая личные чаты, группы и каналы.
Список числовых ID через запятую ограничивает как историю, так и новые сообщения.
Указанный в списке чат должен быть доступен этому аккаунту. После изменения `.env` перезапусти соответствующие сервисы.

`HISTORY_LIMIT=1000` — размер порции старой истории на чат за цикл, а не общий лимит архива.
Каждые пять минут сборщик продолжает с `oldest_message_id`; `latest_message_id` отдельно отслеживает
успешно завершённую догрузку новых сообщений. Catch-up после простоя не ограничивается размером старой порции.
`HISTORY_LIMIT=0` загружает всю доступную старую историю за проход; это может занять долгое время.
`FloodWait` обрабатывается ожиданием. Ошибка отдельного недоступного чата не останавливает остальные.

Новые сообщения, правки и удаления принимаются параллельно истории. Старая версия из истории
не затирает более свежую правку. Старый текст сохраняется в `message_revisions` при наблюдавшемся изменении текста.
В группах адресат — сам чат; в личных сообщениях дополнительно заполнен `recipient_user_id`.
Анонимный администратор/канал записывается в `sender_chat_id`, а не под вымышленным user ID.
Reply ссылается на `(reply_to_chat_id, reply_to_message_id)`; исходное сообщение может отсутствовать в архиве.

Био запрашивается отдельной медленной очередью и перепроверяется раз в сутки.
`bio=NULL` означает отсутствие, недоступность либо ещё не завершённое обогащение;
`bio_checked_at` показывает попытку проверки. Состав участников целиком не выгружается:
таблица пользователей содержит наблюдавшихся отправителей и самого владельца аккаунта.

## MCP

Streamable HTTP URL: `http://127.0.0.1:8765/mcp`.
Клиент должен поддерживать HTTP headers; значение токена возьми из локального `.env`.
Не вставляй токен в README, чат или общую конфигурацию Git.

```json
{
  "mcpServers": {
    "tg-message-collector": {
      "url": "http://127.0.0.1:8765/mcp",
      "headers": {"Authorization": "Bearer <local MCP_TOKEN>"}
    }
  }
}
```

Это пример общего формата: конкретный клиент может использовать другой ключ конфигурации.
С WSL localhost доступен из Windows при обычном localhost forwarding; фактический доступ Windows-клиента
следует проверять отдельно. Глобальная MCP-конфигурация других агентов автоматически не менялась.

| Tool | Назначение |
| :--- | :--- |
| `list_users` | user ID, username, имена и био, фильтр ID/username, пагинация |
| `list_chats` | Основные данные чатов, фильтр ID/username, пагинация |
| `search_messages` | Чат, автор user/chat, даты, тема, ключевые слова и подстрока |
| `semantic_search` | Поиск по смыслу на локальной модели, фильтры чата/автора/дат |
| `get_message` | Сообщение, доступный reply, соседние сообщения, до 200 прошлых текстовых версий |
| `archive_status` | Счётчики, покрытие эмбеддингами, готовность ANN, прогресс первых 200 чатов |

Примеры аргументов:

```json
{"query": "+велосипед* +ремонт", "chat_id": -1001234567890, "sender_user_id": 123456}
```

```json
{"query": "обсуждение починки двухколёсного транспорта", "chat_id": -1001234567890}
```

`search_messages` возвращает `next_cursor` из трёх полей: `before_date`, `before_chat_id`, `before_message_id`.
Передавай все три для следующей страницы. `since` включительно, `until` исключительно; даты UTC.
По умолчанию удалённые сообщения скрыты; `get_message` позволяет прочитать сохранённую удалённую запись явно.
`include_deleted=true` доступно у обычного поиска.

МCP не предоставляет произвольный SQL и не имеет инструментов записи. Read-only ограничение
проверено не только на уровне инструментов: MySQL запрещает reader-пользователю INSERT/UPDATE/DELETE/DDL.
Контент сообщений считается недоверенными данными, а не инструкциями для агента.

## Индексы и ограничения поиска

`messages` использует составной PK `(chat_id, message_id)`: Telegram ID сообщения не глобален.
Отдельный `archive_id` — внутренний ключ векторного индекса.
B-tree индексы покрывают чат+дату, автора+дату, чат+автора+дату,
отправителя-канал, reply и темы форума. Keyset pagination не использует дорогой растущий OFFSET.
Отсутствие FK для reply/автора позволяет сохранять неполную историю и сообщения вне очереди.

FULLTEXT индекс работает по `text`, включая caption. Boolean mode поддерживает `+слово`, `слово*`, `"фраза"`.
MySQL учитывает минимальную длину токена (обычно 3) и stopwords; русской морфологии здесь нет.
Для буквальных коротких слов или фрагментов есть `mode="substring"`; `%` и `_` трактуются буквально.
Подстрока может сканировать строки, поэтому для больших архивов лучше добавить чат/автора/даты.

Семантика использует нормализованные векторы и cosine similarity, а не совпадение слов.
Оценка похожести не является вероятностью. Локальная модель обрезает очень длинный вход до своего окна;
длинное сообщение не индексируется как набор отдельных фрагментов.

- Без фильтров используется HNSW/USearch по всему опубликованному индексу: `approximate=true`.
  Это приблизительный поиск, абсолютный recall не гарантируется. Результаты перепроверяются и
  пересчитываются по актуальным векторам MySQL; удалённые записи и старые текстовые хэши исключаются.
- С фильтрами выполняется точный cosine scan по новейшим `candidate_limit` подходящим векторам:
  по умолчанию 50000, максимум 200000. `truncated=true` явно показывает неполный охват.
  Уточни чат/дату/автора, если область больше лимита.
- До появления первого ANN snapshot общий поиск использует тот же ограниченный точный scan.
- Векторная очередь обновляет только новые/изменённые тексты. Индекс публикуется атомарно,
  обычно не чаще раза в 30 секунд и при опустошении очереди. MCP открывает snapshot read-only.
  При перезапуске worker перестраивает индекс из MySQL; это также удаляет старые tombstones.
  Смена модели требует пересчёта эмбеддингов; разные модели имеют разные snapshot-файлы.

```bash
# Только при остановленном сборщике: обработать весь текущий backlog и выйти.
.venv/bin/python app.py embed --once
```

На миллионах записей следующие улучшения: filter-aware ANN для больших отдельных чатов,
разбиение длинных сообщений на фрагменты, мониторинг очереди и точный benchmark на реальном распределении данных.
Текущие индексы не являются доказательством производительности на ещё не собранном большом архиве.

## Что Telegram не позволяет восстановить

Доступна только история, видимая этому аккаунту. Уже удалённые сообщения, старые правки до запуска,
пропущенные события удаления во время простоя и невидимая история не восстанавливаются.
Удаление без достоверного chat ID попадает в `unresolved_deletions`, без угадывания соответствия.
Файлы вложений не скачиваются: сохраняются caption, тип и метаданные, включая file IDs.
Геолокация поддерживается как метаданные; poll/contact и другие специальные payloads требуют отдельного расширения.

Рекомендуемые следующие шаги: согласовать нужные чаты, срок хранения, локальные резервные копии
базы и сессии с шифрованием, а при необходимости — скачивание вложений и экспорт результатов поиска.
Эти действия не включались автоматически.

## Перенос на другую Linux/WSL машину

Нужны Python 3.12–3.14, `uv`, MySQL 8 и база с utf8mb4.

```bash
uv sync --frozen
cp .env.example .env
chmod 600 .env
# Заполни API/телефон и отдельные database credentials локально.
# Администратором создай базу и accounts с grants, описанными выше.
sudo mysql tg_message_collector < sql/001_archive.sql
.venv/bin/python app.py login
```

Для первого semantic-запроса/индексации нужна загрузка модели (~220 МБ) с Hugging Face;
после кэширования она работает локально. Изменение модели может потребовать другую загрузку.
Подставь абсолютный путь проекта вместо `@PROJECT@` в `deploy/*.service`, скопируй units
в `~/.config/systemd/user/`, затем `systemctl --user daemon-reload` и `enable --now`.
Работа после выхода пользователя зависит от настроек user manager/linger; настройки всего хоста не изменялись.

SQL-схема применяется администратором; runtime-пользователям DDL не выдаётся.
`001_archive.sql` идемпотентен для первичного создания, но не изменяет структуру уже существующей таблицы:
будущие изменения требуют отдельной миграции.

## Проверки

```bash
uv sync --frozen --group dev
.venv/bin/ruff check collector app.py tests
.venv/bin/python tests/test_archive.py
```

Интеграционные тесты создают случайную отдельную MySQL-базу и удаляют только её,
используя локальный `sudo -n mysql`. Проверяются дедупликация, правки, удаления, сериализация
Kurigram, фильтры, SQL-параметры, FULLTEXT query plan, пагинация, продолжение истории,
локальная семантика, read-only grants и настоящий HTTP MCP-клиент с авторизацией/Host-проверкой.
Тестовые тексты не добавляются в рабочий архив.
